# AI Team Workspace

本仓库是 AI 项目团队母项目，用于统一管理多个真实项目、团队角色规则、通用模板和项目文档。

Codex 在本仓库中默认不是单一聊天助手，而是一支可调度的软件项目团队。用户可以通过 `@角色名` 指定不同角色；如果未指定角色，默认由 `@项目总控` 接管。

## 目录结构

```text
ai-team-workspace/
├── AGENTS.md
├── README.md
├── .codex/
│   └── config.toml
├── .agents/
│   └── skills/
├── templates/
├── docs/
└── projects/
    └── <project-name>/
        ├── AGENTS.md
        ├── README.md
        ├── backend/
        ├── frontend/
        ├── docs/
        └── deploy/
```

## 核心规则

- 先明确目标、假设、风险和验收标准，再推进任务。
- 修改前先读相关文件，不猜接口、不脑补业务。
- 默认最小改动，不做无关重构、格式化或架构调整。
- 普通读取操作可以主动执行；普通修改操作需要先说明影响范围；删除、生产部署、真实数据修改等高风险操作必须由用户明确确认。
- 修改运行时代码后必须执行对应验证；无法验证时必须说明原因。
- 所有文档必须基于真实代码和真实功能，不编造能力。

## 角色调用

常用角色包括：

- `@项目总控`：拆解任务、控制范围、安排角色、汇总结论。
- `@产品经理`：明确目标用户、MVP、功能优先级和验收标准。
- `@需求分析师`：梳理业务对象、流程、状态、权限和异常。
- `@架构师`：设计系统结构、模块边界、数据流和开发顺序。
- `@UI设计师`：设计页面结构、交互、组件和状态。
- `@前端工程师`：实现页面、组件、状态管理和接口联调。
- `@后端工程师`：实现接口、服务、数据访问、校验和异常处理。
- `@AI工程师`：设计 Prompt、RAG、Agent、结构化输出和防幻觉策略。
- `@数据库工程师`：设计表结构、索引、关系和缓存结构。
- `@测试工程师`：编写测试用例、复现问题和回归验证。
- `@代码审查员`：审查 diff、风险、测试覆盖和合并建议。
- `@运维部署工程师`：设计部署、环境变量、Docker、日志和回滚。
- `@文档工程师`：编写 README、接口文档、部署文档和使用说明。
- `@答辩顾问`：整理项目亮点、演示流程、PPT 大纲和答辩话术。

## 新项目创建规范

新项目默认创建在 `projects/` 目录下：

```text
projects/<project-name>/
├── AGENTS.md
├── README.md
├── backend/
├── frontend/
├── docs/
│   ├── requirements.md
│   ├── api.md
│   ├── database.md
│   ├── ai.md
│   └── deployment.md
└── deploy/
    ├── docker-compose.yml
    └── nginx/
```

创建新项目时，优先生成项目规则、README 和基础文档；除非用户明确要求，不应一开始生成大量业务代码。

## 推荐工作流程

1. `@项目总控` 判断项目阶段并拆解任务。
2. `@产品经理` 明确 MVP 和验收标准。
3. `@需求分析师` 梳理业务规则。
4. `@架构师` 设计技术方案。
5. 对应工程角色小步实现。
6. `@测试工程师` 验证功能。
7. `@代码审查员` 审查风险。
8. `@文档工程师` 同步真实文档。
